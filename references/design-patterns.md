# 页面用途与版式

## 共同的视觉语言

正文使用站点默认字体。页面已有标题，一般从 h2 开始，h3 用于分组；不要用字号替代标题语义。超过约四个主要章节再考虑目录，短页无需目录。

推荐低饱和配色（可以跟随用户品牌调整）：

| 用途 | 文字/强调 | 浅背景 | 使用方式 |
|---|---|---|---|
| 主信息 | `#0052CC` | `#DEEBFF` | 结论、标题面板、小范围数字强调 |
| 已验证/推荐 | `#006644` | `#E3FCEF` | 推荐行/列、实测通过标签 |
| 待验证/注意 | `#974F0C` | `#FFFAE6` | 条件、待验证状态 |
| 阻塞/失败 | `#BF2600` | `#FFEBE6` | 实际失败或必须处理的问题 |
| 中性 | `#42526E` | `#F4F5F7` | 元信息、方法、辅助面板 |

颜色不是唯一编码：同时标注“推荐”“未验证”等文字。白底正文、浅色面板、深色文字更易读。保留站点默认段落间距，使用原生列布局和 panel 形成留白；不要靠多个空段或空格对齐。

一个屏幕里只安排少量视觉重点。摘要卡适合 2–3 个短结论，不适合塞段落。两列用于并列方案或职责；三列用于短指标；长代码、图表和大表格用单列。窄屏时检查列内文字是否拥挤。

## 实验报告 / 性能评估

顺序建议：

1. 一句话结论 + 环境/日期 + 验证状态。
2. 可选的 2–3 张摘要卡：推荐项、验收结果、关键差值；写清场景和单位。
3. 可见的口径说明：测量的是哪个组件，不包含什么。
4. 主要图表 + 精确数据表；突出推荐列或行。
5. 结论的适用条件、局限和下一步。
6. 折叠的完整方法、环境、分项数据和复现命令。
7. 原始资料附件/链接。

图表帮助比较，不能取代表格和口径。离散选项用柱状图，随时间/长度变化用折线图（先验证站点参数），不为比较接近的延迟值使用饼图。柱状图一般从零开始。统一单位；系列不能把均值、P99 或不同 batch 混在一起。图表标题或相邻文字明确样本、聚合方式和“越低越好/越高越好”。

实测经验：把图表数据按“第一行是类别、后续行是系列”组织，使用 `dataOrientation=horizontal`，再检查生成图片是否确实是一组柱子。该参数是数据读入方向，不能靠名字猜柱子朝向。纵轴标签参数可能被渲染器忽略，因此图表标题/邻近正文也应有单位。

## 技术设计 / 方案比较

顺序：问题与目标 → 推荐方案 → 范围与约束 → 架构/流程图 → 方案比较表 → 接口与实施步骤 → 风险与待决项。

- 使用两列比较独立方案，超过两方案用表格。
- 图需回答职责、数据流或时序问题；已验证 PlantUML 时可用它，否则使用附件图片。
- `status` 表达“草案/待评审/已批准”，不要因为文档写完就标“已验证”。
- 细节推导和长接口示例折叠，核心取舍保持可见。

## 操作手册 / 排障指南

顺序：适用版本与目标 → 前置条件 → 操作步骤 → 成功判据 → 常见问题 → 回退/恢复步骤。

- 步骤用有序列表，命令用带语言的 code 宏。
- 会影响操作选择的警告放在对应步骤前，不藏在折叠里。
- 长日志和异常栈折叠，短成功输出放在命令后。
- 不把所有步骤横向排成卡片，避免阅读顺序不清。

## 项目进展 / 周报

顺序：报告周期 → 本期结果 → 进行中事项 → 阻塞与需要协助 → 下期计划。

- 表格列可用“事项 / 状态 / 负责人 / 下一步 / 日期”；没有来源的负责人和截止日期不能补造。
- 状态宏适合短状态，详细解释用正文。
- 仅当数字有意义且可追踪时使用摘要卡。

## 知识库入口 / 导航页

顺序：使用说明 → 主题分组 → 常用入口 → 最近维护信息。

- 两列或三列 panel 组织主题链接，标签与链接名具体。
- children、page tree、page properties/report 等动态宏在目标站点未验证前不预设可用；可先用普通链接。
- 用户要求在入口下新建文章时，保留入口原文，设置新页面 parent。

## 表格和折叠的细节

- 表头写单位，文本左对齐，数值右对齐，精度一致；不要把单位重复塞进每一格。
- 宽表优先减少列、拆成主题表，避免依赖横向滚动和小字体。
- 只高亮推荐行/列或异常值，少做合并单元格；不要把数据表当整页布局容器。
- 折叠标题写明内容，如“实验环境与采样方法”“展开完整失败日志”，避免全是“更多”。
- 避免多层嵌套折叠；每个宏都有用途，长文也不需要堆满所有宏。

## 发布后的观察点

有浏览器时看标题层次、列宽、长链接、代码溢出、折叠展开、目录跳转和窄窗口表现。只有 API 时检查 view 与生成图片，明确这不覆盖 CSS、浏览器脚本和响应式布局的全部行为。
